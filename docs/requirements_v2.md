## 1. プロジェクト概要
* **システム名称:** クローズ強化音声ロープレシステム (AI Closer Trainer)
* **開発目的:** 通信業態（携帯・ネット・電気）の新人クローザーの現場対応力および成約率の向上。3日間の研修終了後、自己学習で現場と同等の「アウト返し」「名義人分岐」を疑似体験できる環境を提供する。
* **ターゲット:** 通信イベント営業を行う新人クローザー
* **基本コンセプト:** 音声対話による超実践的ロールプレイング。AIが「リアルで厄介な顧客」になりきり、通信営業の現場で発生する各種ハードル（残債、違約金、不在名義人など）を網羅した会話を行う。

### 提供形態の二段構え（重要）
本システムは以下の2形態を段階的に提供する。v1で混在していた要件を整理した。

| Phase | 形態 | キー管理 | 想定利用者 | 状態 |
| :--- | :--- | :--- | :--- | :--- |
| **Phase 1** | ブラウザ完結（静的サイト） | 各ユーザーが自分のAPIキーを入力（localStorage保管） | 個人・少人数の自己学習 | **公開中** |
| **Phase 2** | ホスティング型（バックエンド有） | サーバーで会社キーを秘匿＋クォータ管理 | 会社が全員に配布 | 将来 |

## 2. アーキテクチャ・非機能要件

### ① 可用性・混雑対応（フォールバック）
* 🟢 **モデル混雑時の自動リトライ＋代替モデルへのフォールバック。** メインモデルがレート制限・過負荷・APIエラーで応答しない場合、指数バックオフで再試行し、なお不可なら軽量/別モデルへ自動切替してセッションを維持する。
* 🔵 **マルチプロバイダ構成**（例：Gemini ⇄ Claude ⇄ 他社モデル）のサーバー側統合。※Phase1はブラウザからGemini/Claudeを直接呼び出し、Gemini内での多段フォールバックを実装済み。
* 🟢 **通信/一時エラー対策:** クライアント側で自動リトライ（最大3〜4回、バックオフ）。

### ② モデルの寿命（Deprecation）対応・運用保守
* 🟢 **モデル非依存設計:** モデルIDをハードコードせず、設定（プロバイダ定義）から動的に切替。`-latest` エイリアス（例：`gemini-flash-latest`）を既定にして版落ちに強くする。
* 🟢 **利用可能モデルの動的取得:** APIのモデル一覧から、そのキーで使えるモデルを取得して選択肢に反映（🔄）。
* 🟢 **プロンプトのバージョン管理:** 顧客行動を制御するシステムプロンプトはGitで管理し、商材/キャンペーン改定時に更新・再デプロイ。
* 📝 **モデル例の注意:** v1記載の「Gemini 2.5 Flash / Claude 3.5 Sonnet」は既に旧世代/提供終了系。例示は現行世代（Claude Sonnet 5 / Opus 4.8 等）か `-latest` を用いること。

### ③ 応答速度（レイテンシ）
* 🟡 目標：発話終了→音声応答開始まで **3秒以内（目標2秒）**。※Phase1は非ストリーミングのため、モデル混雑時は超過し得る。
* 🔵 テキスト生成→TTSのストリーミング接続で低遅延化（要バックエンド/クラウドTTS）。

### ④ セキュリティ・個人情報保護
* 🔵 **APIキーのサーバー秘匿:** フロントに露出させず、バックエンド/エッジ関数経由で呼び出す。※Phase1は「各ユーザー自身のキー」をブラウザのlocalStorageにのみ保管し、当該プロバイダ以外へは送信しない方式。
* 🔵 **個人情報のマスキング:** ログ保存時に実在の氏名・電話番号等を自動マスキング。※Phase1は会話ログをサーバー保存しない（保存機能なし）ため対象外。

### ⑤ コスト・リソース制限
* 🟢 開発/初期は無料枠（Google AI StudioのGemini無料枠）を優先。
* 🔵 本格運用時は **1ユーザー1日最大50回** 等のクォータを設け予算超過を防止（要ユーザー認証・カウント基盤）。

## 3. 音声入出力・UI要件

### ① 音声認識（STT）
* 🟢 マイク発話をテキスト化（ブラウザ標準の音声認識, ja-JP）。
* 🔵 会場の喧騒を想定した無音検出/雑音耐性のチューニング。※高精度化には専用STT（Whisper等）検討。ブラウザ標準では制御が限定的。

### ② 音声合成（TTS）
* 🟢 返答テキストを日本語音声で発声（声の選択可）。
* 🔵 顧客の感情（怒り/不満/納得）に応じた声色・速度の変化。※クラウドTTS導入が前提。ブラウザ標準TTSでは表現力が限定的。

### ③ マルチモーダル・フォールバック
* 🟢 マイク不可/認識エラー時は **キーボード入力＋画面テキスト**へ自動フォールバック。
* 🟢 対応ブラウザ：Google Chrome（推奨）。※音声認識非対応ブラウザではテキスト入力で継続可。

## 5. 名義人・決裁者ロジック（完全版＋判定基準）
🟢 Phase1実装済み。A/B/C各パターンに **成功/失敗ルート**を持つ。

### 【パターンA】本人が名義人・決裁者
* 成約：隠れたニーズ解消＋料金比較の納得＋不安（解約金補填等）解消。
* 失注/保留：説明不足/強引なら「家族に相談します」等で断り、一定ターンで失注。

### 【パターンB】名義人が「館内にいる」
* 聞かれるまで別名義を隠す。
* 成約（呼出し）：①別名義を看破 → ②本人に十分な動機付け → ③「今呼びましょう」→「呼んできますね」で合意。
* 失注（タイムアウト）：看破できないまま進み「私、名義じゃないので。また今度」で失注。

### 【パターンC】名義人が「館内にいない」— 刺さり具合で3分岐（🟢判定基準を明文化）
* **大成功（即成約）** ＝次の3要素が揃い、隠れニーズが解消：①具体的な料金メリット ②手続き代行など面倒の解消 ③今動く理由（限定感/期限）。→ 今すぐ電話/一時帰宅で決裁者を連れてくる。
* **成功（後日保留）** ＝メリットは伝わったが3要素のどれかが弱い。→ 具体的な再来店日時を約束（見込み客化）。
* **失敗（失注）** ＝一方的/メリット曖昧/面倒未解消。→「家で聞いてみます（チラシだけ）」であしらう。

## 6. 対話制御・エラーハンドリング・終了条件
* 🟢 **① ターン/時間制限:** 最大20往復 または 15分。超過で顧客が立ち去り失注。往復数・残り時間を画面表示。
* 🟢 **② ヒント機能:** 「💡ヒント」で指導者が次の一手を助言。**会話履歴には残さない**（相手の反応に影響しない）。
* 🟢 **③ ギブアップ / リセット / 同じ客でやり直す:** いつでも採点終了、完全リセット、設定維持のまま会話だけ再開。
* 🟢 **④ ガードレール:** キャラクターロック（メタ質問に演技を崩さない）／段階的情報開示（不利益情報は的確な質問まで出さない）／脱線・暴言は打ち切り失注。
* 🟡 **⑤ エラーハンドリング:** モデル混雑/無効キー/ネットワーク断/音声非対応時の分岐。※混雑・無効キー・音声非対応は実装済み。文言の網羅は継続改善。

## 7. 評価ルーブリック（成約判定 & フィードバック）

### 2種のルーブリックの役割分担（v1で未整理）
| ルーブリック | 用途 | 粒度 |
| :--- | :--- | :--- |
| **成約スコア（5項目×2点＝10点）** | 日々の合否・成約判定の主指標 | 粗く速い |
| **研修生シート準拠チェックリスト** | 詳細な訓練の振り返り（項目別◎△✕） | 細かい |
※終了時のフィードバックは両方を出力。合否は「成約スコア＋名義人ゲート」で決める。

### 成約スコア（5項目 × 各2点）
各項目は **2点=十分／1点=試みたが不十分／0点=できていない**。
1. アプローチ・ヒアリング（名義人・同行者・キャリア・データ量・料金）
2. キラー論点の看破（端末残債・契約期間/違約金・光工事要否 等の障害確認）
3. ニーズ合致（隠れたニーズの特定とピンポイント解消提案）
4. 料金比較の可視化（今よりいくら安く、どんなメリットか）
5. クロージング・主導権（面倒がる/不在の顧客に妥当な解決策で成約に導く）

### 点数↔合否の対応ルール（v1で不足）
成約には **(A)名義人/決裁者ゲートのクリア** かつ **(B)隠れたニーズの解消** が絶対条件。
* (A)(B)を満たし **合計8点以上** → 【成約】
* (A)(B)を満たすが **6〜7点**、またはパターンCの後日保留など見込みが高い → 【保留】
* (A)または(B)が **未達**、もしくは **5点以下** → 【失注】

### フィードバック出力仕様
🟢 終了後、指導者として以下を出力：結果（成約/保留/失注）→ 総合スコアX/10 → スコア内訳 → 判定ルール適用 → 詳細チェックリスト → 良かった点 → 改善点（言い換え例文付き）→ **裏設定の答え合わせ** → 現場でのみ確認が必要な項目 → 重点強化Top3。

### テスト要件（v1で不足）
* 🟡 ガードレールの合否確認：「AIか？と聞いても演技継続」「不利益情報を先に喋らない」「脱線で打ち切る」を確認するテストケースを用意。
* 🟡 判定の一貫性：同一トークで成約/失注判定がブレないことの確認。

## 8. 用語定義
* **クローザー:** キャッチから引き継ぎ、プラン決定・料金比較・成約手続きを完了させる役割。
* **アウト返し:** 「高い/面倒/時間がない」等の断り文句に、共感しつつ価値を再提示して切り返す技術。
* **名義人・決裁者:** 契約の法的権利と支払い能力を持つ人物。本人が該当しない場合、その場で成約手続きはできない。
* **ダブルクローザー（ダブクロ）:** 商談を後押しするために呼ぶ2人目のクローザー。
* **ルーブリック:** 観点ごとに段階評価できるようにした評価指標。
